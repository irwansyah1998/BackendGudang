# Documentation Maintenance

## Purpose
Keep technical documentation aligned with verified implementation.

## Use when
Behavior, API contracts, architecture, dependencies, configuration, testing, CI, or operations change.

## Procedure
1. Read the relevant sections in `Documentation.md` and `docs/architecture/PROJECT_MAP.md`.
2. Update only claims affected by the change; distinguish verified, partial, and planned states.
3. Refresh endpoint, environment, dependency, test, risk, and change-log details as applicable.
4. Do not mark platforms, releases, tests, or deployments verified without evidence.
5. Check commands and diagrams against current files before finishing.

## Acceptance
Documentation describes the shipped state, contains no real secrets, and makes open decisions and verification gaps explicit.
