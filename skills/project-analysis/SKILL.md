# Project Analysis

## Purpose
Establish verified project context before proposing or changing architecture.

## Use when
Starting a task, onboarding to the repository, or assessing a broad change.

## Procedure
1. Check root, Git branch/status, and local changes.
2. Read `AGENTS.md`, `Documentation.md`, and the project map.
3. Inspect only relevant manifests, source, tests, migrations, and workflows.
4. Compare documentation claims with implementation; label unknowns and assumptions.
5. State the smallest change, acceptance checks, risks, and documentation impact.

## Acceptance
No files, endpoints, dependencies, test results, or deployment states are claimed without evidence. Preserve unrelated local changes and request clarification for unresolved decisions affecting security, architecture, or data.
